# APAAR-Based Student Data Management and Verification System — prototype

Smart India Hackathon problem statement **SIH26263** (AICTE). A register of student enrolments for
AICTE-approved institutions, keyed to APAAR ID: validated automatically, monitored against approved
intake, and verifiable with consent.

> **Synthetic data only.** Every person, institution and APAAR ID is synthetic (APAAR IDs are 12 digits
> starting with 9). **APAAR registry verification is SIMULATED** against a synthetic registry table;
> no official APAAR API contract was available. Every screen and API result that shows an APAAR check
> says `SIMULATED`.

The architecture is in [`docs/SIH26263_Architecture_Blueprint.pdf`](docs/SIH26263_Architecture_Blueprint.pdf).
The build brief is in [`docs/BUILD_PROMPT.md`](docs/BUILD_PROMPT.md), and [`HANDOFF.md`](HANDOFF.md) gives the current status.

## Run it

Needs Python 3.11+ and Node 18+.

```bash
make setup     # venv + Python deps + npm install + frontend build
make seed      # reset DB, load synthetic data, write sample_data/ (about 5 s)
make run       # http://localhost:8000  (API docs: http://localhost:8000/api/docs)
```

The same steps as raw commands:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
(cd frontend && npm install && npm run build)
(cd backend && ../.venv/bin/python -m app.seed --reset)
(cd backend && ../.venv/bin/uvicorn app.main:app --port 8000)
```

Docker is optional: `docker compose up --build` seeds and serves on port 8000.

For development, run `make dev` for the backend with reload and `cd frontend && npm run dev` for Vite on :5173, which proxies `/api`.

## What is in the prototype

All of these are complete vertical slices: UI, API, database and tests.

- **Ingestion:** one template; CSV/XLSX upload; preview with 25 named rules; inline correction; "did you mean" for mistyped APAAR IDs; bulk fix; leave out; partial commit and retry; manual entry; idempotent ERP API.
- **Seat ledger:** intake, NRI and each supernumerary category (FN/OCI, CIWG, TFW) counted separately with recorded rule sources. A seat-check API runs before admission, and the upload preview shows a projection.
- **Flags and review:** C001/C002 capacity flags; cross-institution conflicts with the other institution's identity withheld; review workflow (clarify, respond, resolve, dismiss, reopen). Only a capacity flag can be auto-resolved, and only when its condition disappears.
- **Identity resolution:** tuned for Indian names (transliteration folding, initials, token order, Jaro–Winkler), with the weights explained. Nothing is merged automatically.
- **Dashboards:** institution and national dashboards update live over SSE. Review priority combines rule signals with robust peer statistics and always shows the disclaimer.
- **Signed records:** SD-JWT-style records with Ed25519 signatures and selective disclosure, plus QR, a printable certificate showing APAAR ID next to the institution student ID, revocation and a tamper demo.
- **Consent and privacy:** consent-based verification where a match and a no-match look identical to the verifier; student correction requests; masked identifiers for analysts.
- **Audit and security:** hash-chained audit with denied-access logging and chain verification; reports with CSV-injection protection.
